# 小样本 RAG 对照实验

> **这是方法验证，不是效果评估。** 6 道题、一个模型、一份语料、关键词判分——它能说明「检索有没有用」，不能说明「系统准确率是多少」。

## 要验证什么

一个很具体的问题：**课程资料里的特定事实，模型本身知不知道？接上检索后能不能答出来？**

如果裸模型就能答对，说明语料没用；如果裸模型答不出、检索后能答且带引用，才说明 RAG 这条链路有价值。

## 语料

从本人课程资料导出的纯文本（**不在仓库内**，放 `corpus/` 下，已被 `.gitignore` 忽略）：

| 文件 | 内容 |
|---|---|
| `db-course.pptx.txt` | 《数据库原理与应用》课件，176 页，约 2.4 万字 |
| `db-lab.docx.txt` | 同课程实验指导书，约 3.7 千字 |

合计 **57 片、3.0 万字**（约 500 字符一片、重叠 64）。

这组语料的特点是**充满模型不可能预知的细节**：任课教师姓名、开课学期、DBMS 及其版本、数据库命名规则、教材习题页码、报告提交要求。

## 方法

```
两组条件，同一批问题、同一个模型（qwen2.5:7b）：
  A 带检索：bge-m3 嵌入 + 余弦 Top5 → 编号片段 + 系统提示（要求引用、禁止编造）→ 生成
  B 裸模型：同一句问题，不提供任何资料
```

判分：每个问题预设关键词，答案全部包含才算命中。**这是廉价、可复现但不精确的判分方式**——它会低估"部分正确"的回答（见下方第 4 题）。

## 结果（2026-10-30）

| # | 问题 | 带检索 | 裸模型 |
|---|---|---|---|
| 1 | 实验报告的数据库命名规则 | ✅ 答出「学号后四位+姓名+MYSPJ」，引用 [4] | ❌ 给了通用命名建议 |
| 2 | 实验一的 DBMS 与版本 | ✅ SQL Server 2008，引用 [1] | ❌ 「没有具体信息，可能是 MySQL/PostgreSQL…」 |
| 3 | 实验一要建哪几个表 | ✅ S / P / J / SPJ，引用 [3][4] | ❌ 「无法直接提供准确答案」 |
| 4 | 报告除截图外还要写什么 | ⚠️ 答出「实验总结、心得体会」，漏「错误原因」 | ❌ 通用报告结构 |
| 5 | 任课教师与开课学期 | ✅ 张美琪 / 2025 春，引用 [1] | ❌ 「无法了解任课教师」 |
| 6 | 实验一到四命名是否一致 | ✅ 引用了命名规则原文 | ⚠️ 「建议保持一致」，碰巧命中 |

**带检索 5/6，裸模型 1/6。**

## 三个观察

1. **裸模型的失败方式主要是「拒答」而不是「编造」**：多数回答是「资料中没有提到具体信息」。这比幻觉好，但同样无法完成课程问答。
2. **第 4 题暴露了切片粒度问题**：命中「报告要求」那一片，但「错误原因」写在前一节「注意事项」里，硬切把同一主题拆散了。这正是真实系统采用**按章节优先切片**的理由——章节边界就是语义边界。
3. **延迟瓶颈不在检索**：同环境冒烟测得检索 228 ms、生成 5397 ms、端到端约 5.6 s，检索只占 4%。

## 复现

```bash
# 1. 准备语料（自行导出为 txt，放 corpus/）
mkdir -p tools/experiment/corpus
#    db-course.pptx.txt、db-lab.docx.txt …

# 2. 本机 Ollama 需具备 bge-m3 与 chat 模型
ollama list

# 3. 运行
python tools/experiment/rag_ab.py --corpus tools/experiment/corpus
```

结果写到 `results/<时间戳>.json`，含每题两组回答的原文与 Top5 召回来源。

## 能得出 / 不能得出的结论

| 能说 | 不能说 |
|---|---|
| 课程特定事实，裸模型答不出；接入检索后可答且带引用 | 「系统准确率 83%」 |
| 切片粒度会影响召回完整性（第 4 题可证） | 「检索召回率 X%」 |
| 瓶颈在生成侧（占端到端 96%） | 「系统性能优于同类」 |

样本量、单一模型、关键词判分决定了它只能做**方向性验证**。要得到可写进论文的结论，需要：更大题目集（≥50）、人工或双人标注、多种子温度、以及有检索/无检索之外的分级对照（TopK=1/3/5）。
